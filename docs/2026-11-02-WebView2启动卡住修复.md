# WebView2 启动卡住修复

## 问题与证据

旧部署停留在“正在初始化 WebView2”，无启动超时。固定版运行时在受限目录不能正常创建控制器；隔离测试补充应用容器读取权限后，得到 `get_IsBrowserHitTransparent` / `0x8007139F` 错误。

将相同运行时普通复制到用户本地目录后，控制器可以创建。进一步读取进程完整性令牌：命令宿主为 8192（中），工作区 EXE 为 4096（低）。工作区文件继承低完整性标签，程序因此无法写入普通本机缓存。单纯在源码中改缓存路径仍会拒绝访问。

## 修改文件

- `src/Desktop.Core/BrowserRuntime.cs`：从分发包按清单 SHA-256 校验并复制运行时到专用本机缓存，复用有效文件，修复损坏文件，拒绝路径越界；只为该缓存设置应用容器读取/执行权限。
- `src/Desktop.App/Browser/BrowserHost.cs`：异步准备运行时，记录初始化阶段；创建环境、窗口各最多等 30 秒，恢复会话最多 10 秒。
- `src/Desktop.App/MainWindow.xaml.cs`：准备区域显示实际阶段，失败和超时提供可检查的日志位置，关闭时可取消等待。
- `src/Desktop.App/SmokeTest.cs`：验证实际使用随包运行时生成的本机缓存及随包 .NET。
- `tests/Desktop.Core.Tests/BrowserRuntimeTests.cs`：新增缓存复制、损坏修复、清单越界回归。新增测试先失败，修复后通过。
- `scripts/deploy-local.ps1`：普通复制部署到标准用户程序目录；首次迁移并逐文件核对原 Cookie、设置、会话和旧密钥，原资料保留。
- `scripts/dev.ps1`：发布回归副本也在普通用户目录运行；分发排除密钥、资料和启动日志。
- `scripts/verify-portable.ps1`：分发拒绝启动日志，已部署目录允许本机诊断文件。
- `README.md`、`TASKS.md`、`docs/便携版说明.txt`：同步正式入口、首次启动和验收说明。

没有更改 Windows 全局安全设置或系统运行时；.NET 10.0.13、WebView2 156.0.4314.58 仍随 ZIP 分发。

## 使用与复测

1. 运行 `%LOCALAPPDATA%/Programs/ChaoxingStudyDesktop/current/学习通助手.exe`，或项目下 `artifacts/学习通助手.lnk`。
2. 确认进入学习通个人空间，右侧“主页”等按钮可用。
3. 关闭后重新打开，确认仍为已登录页面。
4. 若异常，查看 `%LOCALAPPDATA%/ChaoxingStudyDesktop/browser-startup.log` 和 `startup-error.log`。不要清除浏览器资料。

重建后执行 `scripts/deploy-local.ps1` 更新本机部署，更新前需正常关闭客户端。已有目标 BrowserProfile 时不会再次覆盖登录资料。

## 仍需注意

首次启动需要复制、校验约数百 MB 浏览器文件。工作区内 EXE 仍可能继承低完整性标签，应使用上述正式入口；ZIP 在普通用户目录解压后运行。之前的真实 AI 算术错误答案尚未作为本次启动故障修复的一部分处理，不据此承诺答案正确率。多 Windows/DPI、学校 SSO 和全部真实课程布局仍需另行验证。

附带的临时测试/暂存目录清理被自动审批以策略阻止为由拒绝，因此本次保留相关目录；不影响正式部署、运行时缓存或用户 Cookie。
