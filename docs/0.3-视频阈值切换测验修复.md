# 视频达到阈值后切换测验

## 原因与修复

1. 原逻辑只在“章节目录所在 frame”里寻找任务点。如果目录在外层、视频与测验标签在内层，视频虽已完成阈值，测验仍不会被点击。现从实际含任务点的 frame 推进，同章任务不再依赖章节完成标记。
2. 网页自行播放的视频进入 play() 时会提前返回 playing，未安装进度监听，且没有先判阈值。现在每次接管/轮询先检查阈值，再处理正在播放状态；达到阈值的当前视频暂停并标记完成，随后按原顺序推进。
3. 补充原脚本已有的 .prev_tab 标签识别；“章节完成后自动进入下一节”仅控制跨章节，同章测验推进不被该开关阻断。

多视频仍按页面顺序处理，不因当前视频完成而跳过后续视频；100% 阈值继续等待自然 ended，保留手动暂停、防暂停和答题提交流程。

## 验证

- 新增真实 MainWindow 轮询回归，而非只单独调用网页点击函数：外层目录/内层视频与测验、无目录、关闭自动切章、prev_tab 布局、只点击一次测验、不提前点击下一章。
- 网页先自行播放的 20 秒真实媒体，在达到阈值后且尚未 ended 时必须被标记完成。修复前明确失败“网页已经播放的视频未按阈值完成判定”。
- 低阈值可能在轮询前已经完成，旧多视频验收的等待条件据此允许“已完成”；仍验证视频顺序 [0,1]、不重播第一条和无重复切换。
