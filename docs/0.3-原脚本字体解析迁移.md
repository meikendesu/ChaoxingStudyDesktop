# 原脚本字体解析迁移

## 对照结果

原脚本的 FontDecryptor 使用：查找可访问文档的 font-cxsecret 字体定义 → GM_xmlhttpRequest 下载 → Typr.parse → glyphToPath → JSON.stringify → MD5 后 8 位 → Table.json 字符映射。

客户端此前已使用相同的 Typr、字形路径指纹及映射表，但只搜索当前文档的顶层 CSS 规则，并且网页 fetch 受 CORS 和重定向限制。该差异可导致字体已经正常显示，而原生答题仍报告 font。

本次补齐：

- 当前文档优先，继续搜索可访问的父页面、嵌套 iframe；支持分组与导入规则，按原脚本取优先找到的字体来源，不再因发现多个来源一律拒绝。
- 网页下载失败时使用独立原生字体客户端回退，对应 GM_xmlhttpRequest 的跨域下载作用。不携带模型 Key，不复制浏览器 Cookie。需要认证的字体仍先走网页正常请求。
- 字体字节按 URL 在当前文档内有限缓存，题目变化可重新提取当前使用的字符。
- 同一 Typr 字形路径及 MD5/Table 映射流程，字体字符不直接改写 DOM。为减少字形传输，只计算当前题目使用的字符，未照搬原脚本遍历全部 CJK 范围的开销。
- 原生下载仅接受超星/学习通 HTTPS 域名，逐次校验重定向，限制 8 MB，停止时取消。导航后的旧字体结果拒绝应用。
- 未映射的已收录字形仍阻止生成与提交；字体未收录的普通汉字保留后备字体行为。失败日志包含下载/来源/解析错误或字形及映射数量。

原油猴脚本没有修改，SHA256 仍为 `97A5FC1F324E1887A8C8D08C650856AD5BE2B47340CBC924E4DCDD46D6F5EB23`。
