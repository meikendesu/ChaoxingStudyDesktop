# InvalidOperationException：本地旧配置覆盖根目录配置

## 原因与复现

用户截图中的日志每隔约 30 秒显示 `自动答题未完成：InvalidOperationException`，未说明具体原因。

实际运行的是 `artifacts/portable/current/学习通助手.exe`。项目根目录 `.env` 有完整模型配置，但 EXE 旁另有一份旧 `.env`，只有提供商和密钥，缺少 `CX_AI_MODEL` 与 `CX_AI_ENDPOINT`。按既有优先级，EXE 旁文件生效，配置校验在发起模型请求之前抛异常。修复前实际程序的公开算术检查也返回 `InvalidOperationException`。

没有改变“EXE 旁文件优先”的规则，也没有跨文件自动拼接配置。已将两份原配置备份到忽略目录 `artifacts/config-failure-20261026/`，仅在本机 EXE 旁 `.env` 补齐同一提供商的模型与接口，原密钥、根目录配置保持不变；Cookie 资料保留。真实密钥及配置备份不加入分发包。

## 修改

- `src/Desktop.Core/AiConfiguration.cs`：配置校验一次列出缺失字段，显示实际读取路径；非法接口同样显示路径，不记录配置值。
- `src/Desktop.App/MainWindow.Study.cs`：在配置校验边界记录明确原因，30 秒后重读；设置页显示具体问题，将“根目录 .env”改为“当前 .env”。
- `tests/Desktop.Core.Tests/EnvSettingsTests.cs`：复现完整根配置被不完整本地文件覆盖，检查字段、路径和密钥不泄漏。
- `src/Desktop.App/SmokeTest.QuestionParity.cs`、`src/Desktop.App/SmokeTest.cs`：原生窗口日志回归，验证无效配置不调用模型、不提交、不泄漏密钥。
- `scripts/verify-portable.ps1`、`scripts/dev.ps1`：部署目录检查显式允许保留用户 `.env`；暂存目录默认严格检查，打包及隔离验收继续排除用户配置和登录资料。
- `README.md`、`TASKS.md`、本说明：记录故障原因及复验步骤。

## 使用与复验

打开 `artifacts/portable/current/学习通助手.exe`，在设置页检查当前模型与接口，留空密钥不会覆盖已有密钥。若以后再次配置失败，按日志给出的文件路径补齐字段；不要只修改另一份未生效的 `.env`。

自动回归命令：`scripts/dev.ps1 test`、`scripts/dev.ps1 smoke`、`scripts/dev.ps1 smoke -Published`。检查带本地配置的部署目录使用 `scripts/verify-portable.ps1 -Path artifacts/portable/current -AllowUserData`。更新前正常关闭旧进程；ZIP 继续要求自行安装 .NET 10 Desktop Runtime x64 和 WebView2 Runtime。
